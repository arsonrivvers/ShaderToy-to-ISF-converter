### Family A: WebGL Fluid Simulation port (day18_01–05) — 5 files
- **Purpose & visual identity**: Direct ISF port of Pavel Dobryakov's WebGL-Fluid-Simulation (Navier–Stokes dye/velocity solver). Generator. Swirling colorful dye plumes with bloom/sunrays and auto-splats.
- **Architecture**: Complexity 5. Staggered fluid solver: curl → vorticity confinement+splats → divergence → pressure clear → 11–20 Jacobi pressure iterations (one ISF PASS per iteration) → gradient subtract → velocity advection → dye advection, all at 1/4 res (`$WIDTH/4`); full-res persistent `dyeBuffer`; then bloom (v03+ uses a full mip chain: prefilter → downsamples to /64 → additive upsamples) and a 16-tap radial sunrays blur; final composite. `velocityBuffer`, `pressureBuffer`, `dyeBuffer` PERSISTENT+FLOAT.
- **Techniques**:
  - Jacobi solver unrolled as N discrete PASSES targeting the same persistent buffer — the canonical ISF workaround for iterative solvers (no cross-pass loops).
  - Hand-rolled `bilerp()` (4 taps + mix) for sub-texel advection sampling.
  - Soft-knee bloom prefilter (curve0/curve1/curve2 quadratic knee) exactly matching Dobryakov's original.
  - Vorticity confinement force from curl-magnitude gradient with `force /= length(force)+0.0001` normalization guard.
  - Interleaved gradient noise dithering (`fract(52.9829189*fract(dot(coord, vec2(0.06711056,0.00583715))))`) on bloom to kill banding — later removed with comment "Dithering removed completely to fix graininess" (documented self-correction).
  - `dt = min(TIMEDELTA, 0.016666)` clamping — protects the sim from frame hitches.
- **Control/UI**: 15–19 inputs; two `event` triggers (reset, addSplat); enable-bools paired with early-exit passes that write a defined neutral value; separate coarse (intensity) / fine (threshold, soft knee) bloom controls.
- **Version evolution**: v01 baseline port → v02 adds `isf_Mouse`/`isf_MouseLast` interaction with an explicit "Normalize coordinates!" fix (mouse comes in pixels, sim wants norm) → v03 "Enhanced" adds `#define PASS_*` named constants, mip-chain bloom, sin-free hash3 ("avoids sin() precision issues"), shading (dye-gradient normal + diffuse), gradient-subtract boundary conditions, background-color blend, early-exit passes for disabled features → v04 preset tuning toward violent motion (curl 50, splatForce 20000) plus sunrays changed from multiplicative (`c *= sunrays` masked shadows to black) to additive (`c += sunrays*0.2`) — bug documented in comment → v05 fixes splat radius (`/100.0` "too small" → `/40.0`) and adds stationary-click outward push so a held mouse still injects motion.
- **Complexity tier**: 5 — multi-buffer multi-resolution simulation with 21–39 passes and conductor-style enable groups.
- **Signature moves**: pass-unrolled solvers; buffers at divided resolutions declared via `$WIDTH/4` … `$WIDTH/64`; comment trail of dated fixes left in shipped code.
- **Rough edges**: the PASSES JSON block with 20 identical pressureBuffer entries is fragile (iteration count changes require editing header + #defines); mixed `IMG_NORM_PIXEL` vs `texture2D` (texture2D used inside functions taking a `sampler2D` arg since the IMG_ macros bind to declared names only).

### Family B: "The Wall Becomes the Door" agent-path series (day18_06, 07, 08) — 3 files
- **Purpose & visual identity**: A single glowing particle walks the screen leaving a persistent trail; on crossing its own trail it turns 90° ("the wall becomes the door"), with a curl-noise pseudo-fluid advecting a colored smoke layer behind it. Generator.
- **Architecture**: 7 passes (v1): half-res persistent velocity sim, **1×1 persistent `pathState` buffer** (pos.xy, angle, totalDist), full-res trail history, intersection-flash buffer, fluid dye, glow blur, composite. v2 (day18_08) expands to 8 passes with a **2×2 `particleState` register file** (cell 0 = pos/prevPos, cell 1 = angle/turnCooldown/totalDist/turnCount, dispatched by `floor(isf_FragNormCoord*2.0)` cell index), a dedicated trail-gradient pass, and a `doorEvents` pulse buffer.
- **Techniques**:
  - **Pixel-as-register state storage**: scalar simulation state kept in tiny persistent FLOAT buffers read at fixed coords (`IMG_NORM_PIXEL(pathState, vec2(0.5))`, `IMG_PIXEL(particleState, vec2(1.5,0.5))`). Comment in day18_06 warns "In Pass 1 (State), RENDERSIZE is 1x1. We must be careful!" and reads `IMG_SIZE(velocityBuffer)*2.0` to recover the true aspect ratio inside the 1×1 pass — a real multi-resolution-pass gotcha and its fix.
  - Defensive init: `needsInit = resetSimulation || TIME < 0.05 || (pos≈0 && totalDist≈0)` — triple guard against unzeroed persistent buffers.
  - Correct angular interpolation toward fluid direction: `angleDiff = atan(sin(diff), cos(diff))` to normalize to −π..π before blending.
  - Trail buffer packs three channels: `.r` = accumulated trail (`max(existing*persistence, newMask)`), `.g` = previous frame's value (used by the intersection detector so the head doesn't trigger on its own fresh paint), `.b` = current-frame-only mask (drawn white-hot in composite).
  - v2's **anticipatory sensing**: forward raycast to `screenPos + dir*senseDistance` sampling the trail gradient, plus left/right "whiskers" at ±perpendicular*0.7, turn direction chosen toward the emptier side, with a `turnCooldown` debounce timer; `sdSegment()` used to draw a continuous capsule stroke between prevPos and pos (no gaps at speed).
  - Door events: turns detected via `turnCooldown > 0.14` inject both a visual flash and a radial velocity pulse into the fluid — event coupling between the agent and the fluid substrate.
- **Control/UI**: 10–12 inputs; v1-fixed version (day18_05-style "Fixed Coordinate Space" variant, day18_06 here) introduces label-only group divider inputs (`{"LABEL": "Movement", "NAME": "Movement_Group", ...}` zero-purpose floats as section headers).
- **Version evolution**: day18_06 (fixed coordinate space; pixel-true line thickness vs RENDERSIZE, robust (0,0) init check) → day18_07 (tightened: randomized turn direction via `hash(TIME,totalDist)` so paths don't loop; `hitBoundary` flag prevents wall bounce and path-turn firing the same frame; weighted-kernel glow) → day18_08 v2 full redesign (reactive → anticipatory; 1×1 → 2×2 state; door-pulse event system; sense-point visualization drawn in composite with green→red alert color by trail proximity).
- **Complexity tier**: 4 — multi-buffer agent simulation with event coupling, but single agent and modest pass count.
- **Signature moves**: register-file-in-texture; whisker steering; debounced cross-pass state machines; drawing debug/UI info (sense points) directly into the final composite.
- **Rough edges**: v2's cells 2–3 of the 2×2 state buffer are dead (pass-through `gl_FragColor = IMG_PIXEL(...)`); state logic duplicated between cell 0 and cell 1 branches (both re-derive shouldTurn) — a consistency hazard the author tolerated.

### Family C: Volumetric "ghost" tunnels — Luminous Labyrinth (day18_09) + Truchet Path (day18_10) — 2 files
- **Purpose & visual identity**: Camera flying through an infinite gyroid labyrinth (09) or randomized 3D Truchet pipe network (10), rendered as translucent glowing density rather than hard surfaces, with luminance-flow trails, separable bloom, and de-band dithering. Generators.
- **Architecture**: 5 passes: raymarch → persistent trail/advection buffer → H blur → V blur → composite+dither. Clean per-pass helper functions (`renderLabyrinth()`, `renderTrails()`, `blurH/V()`, `composite()`) dispatched from a compact `main()` switch — the tidiest code style in the batch.
- **Techniques**:
  - **Transparent density-accumulation raymarch** (the family's signature): `localDensity = max(0.0, window - abs(d))`, front-to-back accumulate `col += localColor*(1.0-density); density += localDensity;` break only at `density>=1.0`. Comments explain "abs(d) ensures we detect walls even if we are inside them."
  - March step `t += max(0.05, abs(d)*0.6)` — enforced minimum step deliberately pushes rays *through* walls instead of converging at d=0 (required for the density model; documented).
  - Gyroid SDF `dot(sin(p), cos(p.yzx))` morphed against a second time-offset frequency; scale-corrected return `dist * (0.6/Lab_Scale)`.
  - Truchet cell: `hash(id+TurnSeed)` selects axis rotations (`uv.xy *= rot(PI/2)` gated by hash thresholds), geometry = min of two corner quarter-torus tubes `length(vec2(length(uv.xy±0.5)-0.5, uv.z)) - PathThickness`, optional third diagonal at hash>0.8. Palette indexed by `length(floor(p*GridScale))` so color bands follow grid shells.
  - Luminance-gradient trail advection: flow = perpendicular of the trail buffer's luma gradient (`vec2(-(T-B), (R-L))`), plus slight center-suction `-(uv-0.5)*0.002`, then `max(curr, prev*decay)` trail merge.
  - IQ cosine palette with hue offsets `(BaseHue, BaseHue+0.33, BaseHue+0.67)`; Reinhard tonemap + gamma + triangular dither in composite (`(fract(sin(dot(uv, vec2(12.9898,78.233)+TIME))*43758.5453)-0.5)*2.0 * DitherAmt * 0.05`) — explicitly labeled "The Fix for Gradient Lines".
  - Perceptual slider mapping: `mapBloomSize(s) = mix(4.0, 40.0, s*s)` — squared response for finer low-end control.
- **Control/UI**: ~12 inputs with ALL-CAPS prefix grouping (`TUNNEL:`, `PATH:`, `CAM:`, `FX:`, `COLOR:`); camera exposed as Yaw/Pitch/FOV — VJ-performable camera.
- **Version evolution**: Truchet is a geometry-module swap on the identical 5-pass Labyrinth pipeline (same trail/blur/composite code, same camera helper), showing a reusable "volumetric tunnel chassis" the author re-skins per geometry. Truchet drops the `TrailsDecay`-blended fallback path and hardcodes intensity 8.0 in accumulation — quicker, looser derivative.
- **Complexity tier**: 4 — raymarching + feedback + post chain, single simulation buffer.
- **Signature moves**: ghost-density raymarching; per-pass function decomposition; post-tonemap triangular dither as standard banding fix.
- **Rough edges**: `rd.xy *= rot(TIME*0.05)` twist applied after camera basis construction slightly fights the Yaw/Pitch controls; blur passes always run even when BloomAmount≈0 (early-exit only returns pass-through sample, still full cost).

### Family G: Datamosh suite (day18_Alt_1 through Alt_14, minus none — 14 files) — the batch's dominant lineage
- **Purpose & visual identity**: Real-time datamosh/compression-artifact **filter**: Lucas-Kanade optical flow between input and a persistent previous frame, flow warped through a library of algorithms/modifiers, then a persistent mosh buffer advected by that flow (P-frame smearing), with I-frame resets, macroblocking, chroma corruption. Complexity 5 across most of the family.
- **Architecture (converged Pro IV/V form)**: 11 passes: previousFrame (persistent) → flowFieldRaw (3×3-window Lucas-Kanade, Cramer's rule solve, magnitude compressed `pow(mag,0.7)*0.15`) → quadtreeMap (recursive variance-driven subdivision, depth ≤6, encoded as vec4(depth, originX, originY, size/256)) → quadtreePersist (temporally stabilized) → flowHistory0/1/2 ring shift → modifiedFlowHistory → modifiedFlow (the modifier chain) → moshBuffer advection + color rack → final/visualize.
- **Techniques** (the heart):
  - **From-scratch Lucas-Kanade optical flow** — 3×3 window accumulating structure tensor + temporal gradient, det-guarded 2×2 solve. Reproduced near-verbatim in all 14 files.
  - **60+ algorithm flow-transform library** in 7 dispatch categories — Basic (multiply/add/axis-isolate/zoom/zoom-sin/shear), Spatial (12 x/y/inverse gradient masks), Average (history and neighborhood averaging over 3 persistent history buffers), Mirror (flow sampled from mirrored UVs), Sweep (4 wipe gates driven by slider or `fract(TIME*accel)`), Sinusoidal (24 variants incl. 5 taper families: linear, center-tent, smoothstep-window, exponential), Experimental (swap, random, 4 block-random scales). The most reusable generator ingredient in the batch — a vector-field-distortion DSL.
  - **Modifier chain** applied in fixed order after the algorithm: luma-weighted curl-noise turbulence ("bright areas melt more, dark areas stay rigid": `weight = luma*0.8+0.2`), vortex rotation `strength/(dist*5+0.2)`, inverse-square gravity attractor, motion exaggeration `pow(mag, 1/exag)*exag` with directional bias, **flow polar quantization** (angle snapped to N steps of TAU, magnitude to M steps), shatter, Sobel edge-explosion (perpendicular flow burst at edges with random sign), flow feedback (self-reinforcement from modifiedFlowHistory), momentum (`h0-h1` velocity extrapolation), temporal displacement (weighted sum over 3 history frames), pixel-grid snapping of flow vectors, soft-knee threshold gate (`smoothstep(threshold, threshold+0.05, mag)` replacing an earlier hard cutoff — documented "UPGRADE: Soft Knee Threshold").
  - **Recursive quadtree macroblocks**: per-pixel loop descends from baseBlockSize, splitting while 5-point flow variance (`computeBlockFlowVariance`: center+4 corners, variance from mean) exceeds `splitThreshold * pow(recursionDecay, depth)`. Five **split styles**: Binary 50/50, Golden ratio (φ alternating orientation per depth), Flow-directed (split axis chosen by flow angle), Random, Spiral (`depth*PHI` rotation). Genuinely models MPEG variable block-size motion estimation.
  - **Asymmetric quadtree temporal response** (Pro IV/V pass 3): depth increase → blend at `detailAppearSpeed` (0.8); depth decrease → `detailFadeSpeed` (0.1); stable → `1-blockInertia`. Author's comment: "the key to grid degradation" — detail appears instantly, ghosts away slowly.
  - **Block-coherent advection**: instead of per-pixel `uv - flow`, the whole block translates rigidly (`sourceBlockOriginPx = blockOriginPx - blockFlow*RENDERSIZE; sourcePixel = sourceBlockOriginPx + localOffset`) — this is what makes it read as codec macroblocks rather than liquid smear.
  - **Grid degradation** (`applyGridDegradation`): depth-gated "frying" — saturation boost scaled by `smoothstep(depthThreshold,1,depth)`, temporal noise injection (optionally fbm multi-octave in Pro V), rare inversion flicker (`hash>0.95`), occasional desaturation, per-channel drift. Pro V adds fractal layers.
  - **Corruption styles**: (0) burst — coherent `simplexNoise(blockID*0.1 + TIME*speed)` so neighboring blocks corrupt in waves; (1) random screen sample "true MPEG glitch"; (2) block swap preserving intra-block offsets. Earlier versions also had hardcoded green/magenta corrupt blocks ("common in MPEG corruption"). The evolution 1→0 carries the explicit lesson: relative offsets fix "the 'Random Sticker' look".
  - **Color-science rack (Pro V)**: true chroma subsampling modes (4:4:4/4:2:2/4:2:0/4:1:1 via quantized chroma sampling grids in YCbCr), rotational chroma separation (Cb/Cr sampled at time-rotating opposite offsets), flow-based chroma drift (R lags flow, B leads at half rate, G anchored), separate luma/chroma bit-depth quantization in YCbCr space, color bleed (chroma mixed from left neighbor — analog smear), Bayer-2×2+temporal-jitter dithered posterization with per-channel option, gamma distortion, wave folding (`abs(mod(c*(1+amt*2), 2)-1)`), bit crush, scanlines.

  - Flow visualization mode in every version (angle→RG, magnitude→B) plus quadtree border overlay — built-in debugging UI shipped in the control panel.
- **Control/UI**: Up to ~60 inputs in Pro IV/V, organized with **`{"LABEL": "═══ CORE CONTROLS ═══", "NAME": "label_core", "TYPE": "float", "MIN": 0, "MAX": 0}`** zero-range floats as section dividers (CORE / TIMING & RESET / RECURSIVE QUADTREE / ALGORITHM SELECTION / FLOW MODIFIERS / CHAOS / COLOR SCIENCE / TEMPORAL / VISUALIZATION); `long` dropdowns with VALUES/LABELS for algorithm category, split style, corruption style, chroma subsample mode; `globalAnimSpeed` master conductor multiplying TIME everywhere (`gTime`).

### Family H: Lincoln Lab Studio Master (day19_01–05) — 5 files, CRT/analog mastering filter
- **Purpose & visual identity**: Single-pass CRT + broadcast-mastering filter: chromatic aberration, signal bleed, interlace jitter, phosphor aperture grille, scanlines, phosphor burn, bloom, plus (later) palette mapping, bit crush, Bayer dithering, and a 16th-scanline XOR glitch. Filter; the only zero-state family in the batch (no PASSES/persistent buffers at all).
- **Architecture**: One pass; pipeline = sampleSource (pixelate → quantize → palette) ×6 taps for aberration/bleed → mastering rack (gun gains → saturation → contrast/brightness → gamma) → CRT stage (dither/noise → phosphor burn → aperture mask → scanlines → threshold bloom). Complexity 3.
- **Techniques**:
  - Per-channel double-tap chromatic aberration: each channel = `mix()` of two samples (shifted, shifted−bleed), aberration scaled by `(1.0 + dot(dc,dc)*5.0)` — edge-weighted, lens-like.
  - Interlace "Edge Zipper": alternate scanline-pairs offset horizontally by `(oddEven-0.5)*2.0*Interlace_Jitter`.
  - Analytic aperture grille: three 120°-phased cosines over `uv.x * Phosphor_Density * 3.0`, sharpened by `pow(mask, sharpness)` where sharpness *decreases* with local brightness (`growth = intensity*Beam_Growth`) — beam blooming over the shadow mask, plus energy renormalization `mask /= max(0.1, 0.3*(1.0-growth*0.5))`.
  - Phosphor burn: `max(0, luma-0.6)` tinted orange (`vec3(1.0,0.6,0.1)`) fading to white as Master_Sat drops — over-driven phosphor color shift distinct from bloom.

- ALL-CAPS `SECTION:` label prefixes and, in the biggest panels, zero-range float inputs as `═══ SECTION ═══` dividers — universal workaround for ISF's missing input groups.
