# Phase 1.5 — WKWebView Fetching (no API key) — Design

**Date:** 2026-06-08
**Status:** Approved approach + key decision + feasibility validated; pending implementation plan
**Builds on:** Phase 1 (merged to master)

## Problem

The Phase 1 fetch path uses Shadertoy's official API, which requires a **Silver/Gold
membership** the user does not have. The classic non-API trick (`POST /shadertoy`) is now
behind **Cloudflare bot protection** — a plain URLSession/curl POST returns a Cloudflare
"Just a moment…" challenge page, not JSON. We need a fetch path that works for any **public**
shader, with no key, that is cheap and low-risk (won't get flagged/blocked).

## Validated approach

Fetch through a real browser engine: an offscreen **`WKWebView`** loads the shader's view
page; WebKit solves Cloudflare's managed challenge unattended (verified ~8s in a real browser),
obtaining the `cf_clearance` cookie. We then run `fetch('/shadertoy', …)` via JavaScript inside
that authenticated page origin to retrieve the shader JSON.

**Feasibility proven (2026-06-08)** with a real browser against `Ms2SD1` (Seascape):
- Cloudflare challenge auto-cleared (title "Just a moment…" → "Seascape").
- In-origin `fetch('/shadertoy', {method:'POST', body:'s={"shaders":["Ms2SD1"]}&nt=1&nl=1&np=1'})`
  returned HTTP 200 with the full shader.
- **Response is a JSON array** `[{ver,info,renderpass}]` — not the API's `{"Shader":{…}}` wrapper.
- Served as `text/html` content-type but the body is JSON — parse by content, ignore the header.

Why this satisfies the constraints:
- **Not expensive:** local WebView, no services/API/hosting. One page-load per user-triggered
  conversion. Nothing recurring.
- **Low flag-risk:** genuine browsing, not scraping-in-disguise. No header spoofing, no
  challenge-bypassing. One request per click is indistinguishable from a person opening the page.
- **Honest caveat:** a rare interactive Cloudflare challenge (Turnstile) would require the user to
  click once in a visible WebView; the clearance cookie then persists. v1 handles the common
  managed-challenge case headlessly and surfaces a clear error otherwise (with the API-key
  fallback as the escape hatch).

## Decision (user-approved)

Keep the keyed API client as an **optional fallback**. Default path = WKWebView fetch. The API
key field in Settings becomes optional, labeled "Advanced: API key (Silver+ members only)". If a
key is present, use the API client; otherwise use the WebView fetcher.

## Architecture

A small protocol unifies both fetch strategies; the conversion engine is unchanged.

```
protocol ShaderSourceProviding { func fetchShader(id: String) async throws -> Shader }
```

| Unit | Where | Role |
|---|---|---|
| `ShaderSourceProviding` | Kit | the fetch abstraction AppModel depends on |
| `ShadertoyClient` (existing) | Kit | conforms; the keyed API path (already `async fetchShader(id:)`) |
| `ShadertoyInternalParser` | Kit | decode internal endpoint array `[Shader]` → first `Shader` (testable) |
| `WebKitShaderFetcher` | **App** | conforms; WKWebView load → challenge wait → JS fetch → parse. Lives in the App target so the Kit stays headless/pure-Foundation and unit-testable. |
| `AppModel` (modified) | App | picks the provider: key present → `ShadertoyClient`; else → `WebKitShaderFetcher` |

WebView fetcher flow:
1. Reuse one `WKWebView` instance (persistent data store → clearance cookie persists across fetches).
2. Load `https://www.shadertoy.com/view/{id}`.
3. Poll until `document.title !== "Just a moment..."` (and a shader marker is present), timeout ~20s.
4. `callAsyncJavaScript` the in-origin `fetch('/shadertoy', …)`; get the JSON text.
5. Parse via `ShadertoyInternalParser` → `Shader` → hand to the existing `ISFConverter`.

## Error handling

| Condition | Behavior |
|---|---|
| Challenge not cleared within timeout | Clear error: "Couldn't get past Shadertoy's bot check — try again; or add an API key in Settings." |
| Shader private / not found | Endpoint returns an error/empty array → "Shader not found or not public." |
| Network offline | Surfaced error with retry |
| API key present but invalid | Existing Phase 1 `shaderNotAccessible` handling |

## Testing

- **Unit (Kit):** `ShadertoyInternalParser` decodes a fixture of the real array response
  (`internal_seascape.json`) → asserts name + renderpass. `ShaderSourceProviding` stub round-trip.
- **Unit (App):** AppModel provider-selection logic (key present vs absent) via an injected
  factory — no network.
- **Integration (App, network-gated):** one real test that fetches a live single-pass shader
  (`Ms2SD1`) AND a live multi-pass shader through `WebKitShaderFetcher`, runs `ISFConverter`, and
  asserts the `.fs` contains expected ISF tokens. Run once to prove the path; marked as requiring
  network (skippable in routine runs).
- **Manual:** launch app with no key, paste a public URL, Convert, Save, load in VDMX.

## Non-Goals (Phase 1.5)

- Interactive-challenge UI (showing the WebView for Turnstile) — deferred; error + API-key
  fallback covers it for now.
- Sound/cubemap/VR passes (unchanged from Phase 1: warn + skip).
- Live ISF preview — still Phase 2 (will reuse this WebView infrastructure).
